# FA база — Telegram-бот и панель модерации

Авторский проект для проверки записей по Telegram username/ID, каталога гарантов, заявок на модерацию и предложений сделок. Владелец проекта: **@mops_garant**. Исходный проект создан с нуля, не копирует чужие изображения или тексты.

## Возможности

- `/start`, `/help` — старт и команды с меню; `/check @username` или `/check 12345678`, а также `/check` ответом на сообщение; `/me`; `/info`.
- `/garants` — каталог гарантов, 5 профилей на странице, страны/каналы/комиссии, листание.
- `/report` — отправить жалобу с доказательствами на *ручную* модерацию. Обвинения не публикуются автоматически; есть `/appeal`.
- `/deal @username` — поэтапный подбор ценностей (MM2, деньги, робуксы и др.), сумма сделки, ссылка контрагенту, согласие/отказ, уведомление администрации.
- `/binddeal ID` внутри вручную созданной администратором группы, бот создаёт приглашение при наличии прав. **Telegram Bot API не умеет создавать обычные группы по команде бота**.
- `/admin` — закрытая Telegram-админка по списку `ADMIN_IDS`; `/add_garant`, `/add_sckam` (так же `/add_scam`), `/add_comn`, `/delete_garant ID`, `/delete_record ID`.
- Веб-админка `/admin` под паролем: статистика, гаранты, публикации, обработка жалоб, список сделок. Защита session cookie, CSRF, серверная валидация.
- PostgreSQL (рекомендуется для Railway) или SQLite (только для локального тестирования). Журнал действий модераторов.

## Запуск в Railway

1. Создать Telegram-бота через [@BotFather](https://t.me/BotFather) и получить `BOT_TOKEN`. **Никогда не добавляйте токен в GitHub.**
2. Развернуть проект Railway из GitHub-репозитория. Файл `Dockerfile` служит конфигурацией запуска, веб-сервер слушает переменную `PORT`.
3. Подключить шаблон PostgreSQL в этом же проекте. В переменных приложения установить `DATABASE_URL=${{Postgres.DATABASE_URL}}` (если сервис БД называется `Postgres`). Нужна постоянная БД, **SQLite в файловой системе Railway может потерять данные при передеплое**.
4. В Railway → Variables установить `BOT_TOKEN`, `ADMIN_IDS` (числовые Telegram ID через запятую), `WEB_ADMIN_USER`, `WEB_ADMIN_PASSWORD` (сложный пароль), `SESSION_SECRET` (случайная длинная строка). `WEB_ADMIN_PASSWORD` и `SESSION_SECRET` обязательны для веб-админки.
5. Создать публичный домен для сервиса Railway в Networking. По `https://ваш-домен/admin` будет вход в веб-панель. `https://ваш-домен/health` покажет статус процесса.
6. Опционально заменить `CHANNEL_URL`, `REPORT_URL`, `GARANT_CHAT_URL`, `APPEAL_URL` на **свои** ссылки. По умолчанию это профиль владельца @mops_garant, чтобы не вести пользователей в чужие сообщества.
7. В Telegram открыть вашего бота, отправить `/start`, после входа в список админов — `/admin`.

## Примечания о безопасности и ограничениях

- Привязка скама только по username уязвима к переименованию или повторному использованию username. Проверки по Telegram ID надёжнее; бот сохраняет ID известных пользователей. Не считайте отсутствие записи доказательством безопасности.
- Ссылки приглашения в группы следует выдавать только участникам. Для привязки сделок бот должен состоять в группе с разрешением создавать ссылки-приглашения.
- Все подтверждения претензий вручную проверяются модератором. Не загружайте в реестр приватные адреса, телефоны и другие личные данные.
- Эта версия не удерживает средства и не выполняет фактическую передачу игровых предметов: бот — инструмент согласования и модерации, не платёжный эскроу.
- Один экземпляр бота на одном токене при long polling. Не запускайте второй процесс параллельно.

## Локально

```
python -m venv .venv
pip install -r requirements.txt
cp .env.example .env
# Задайте переменные окружения любым удобным способом
python -m fa_base.server
```

## Структура

`fa_base/bot.py` — Telegram-команды и FSM; `fa_base/server.py` — веб-панель; `fa_base/db.py` — SQLAlchemy модели; `fa_base/config.py` — настройки; `fa_base/utils.py` — валидация; `fa_base/keyboards.py` — меню.
